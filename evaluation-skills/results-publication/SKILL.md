# 结果公示材料

让获准读者准确查阅已确认的评价结果、奖项及办理要求。这个环节负责表达决定，不负责作出决定；得分相同或排名靠前都不自动改变获奖名单。

结果可对应活动、项目阶段或其他业务区间。业务时间、数据截止、文件版本与发布日期分别保留，不把生成日期当作评价区间。

## 从已确认内容和公示用途开始

资料不足时，简短引导：“把已确认的结果、需要公示的名单和现有模板发给我，再告诉我给谁看。我会整理成公示稿，尚未确认的内容会单独标出来。”

读取用户现有文档、表格和确认记录，识别结果、名单、办理要求、模板及读者范围，不要求用户填写专用配置表。名单可以明确为空；“已确认本次没有奖项”与“还没收到获奖名单”不是同一种状态。

核对各项内容对应同一业务范围、数据与规则版本，确认记录覆盖了实际要公示的对象及条目。读者范围尚未明确时，先确认范围，不把全部明细放进可外发版本。

## 将可公示内容与待确认事项分开

| 遇到的情况 | 处理 |
| --- | --- |
| 名单与结果均已确认且版本一致 | 按记录转写，保留对象身份、奖项及要求，不另行推理 |
| 排名存在但获奖名单未确认 | 不由排名自动选获奖者；相应内容保留待审 |
| 名单缺失、版本冲突或要求未批准 | 输出带待审标识的草稿和具体确认事项，不混成正式文本 |
| 已批准内容明确没有奖项或整改要求 | 按模板省略或说明，不为了填满栏目创建条目 |
| 有内部诊断建议但无正式决定 | 不转成公示整改要求，不带出待验证原因 |

只暂停依赖缺项的内容，其余可整理为草稿。“待审”标识放在实际公示正文和各导出版本中，不只放在聊天回复或正文外的审核说明里。缺少正式模板时可先给出中性排版草稿，请用户确认格式，不伪造机关名称、固定文号、落款、印章或审批意见。

## 按模板准确转写决定

先识别模板的固定段落、待填字段、名单表格和附表位置。保留已批准文字及顺序；发现固定文字与本次确认结果矛盾时提出冲突，不为了完成填充而自行改写制度。

逐条核对对象代码与显示名称，名称或归属变更有适用映射才替换。奖项名称、次数、并列处理、任务内容、责任人与期限照确认记录转写，不把一个人的多个奖项误删为重复，也不凭排名补入另一人。

评价说明只采用已确认表述。复核、异议或办理途径仅使用提供的真实渠道，不虚构联系人、邮箱和受理期限。

附表按批准的公示对象范围和顺序排列，并与该范围名单核对完整性。公开范围小于原始主表时，不为“全量”泄露范围外对象。缺项、未参评和估算状态保留；展示补值不掩盖原始缺项，也不替未参评对象生成名次。

## 文档与图卡使用同一份内容

根据用户要求制作可编辑文档、同版PDF和公示图卡。图卡集中展示已确认结果及办理摘要；长名单可分图或放文档附表，不缩成不可读长图，也不能删去改变含义的条件。

各格式从同一组确认内容生成，统一对象、奖项、要求、时间、版本和状态。图卡中的文字和数值来自确认记录，不由图像生成工具推算事实。

只保留读者需要且获准查看的信息。内部来源路径、审批附件、其他对象诊断、工资、联系方式等不因出现在输入文件中就进入公示；假名替换不代表实际经营数字已获准公开。具体公开字段以本次授权为准。

## 核对后交付待发送文件

逐对象、逐奖项、逐要求对照确认记录，核对附表对象数及缺项状态，检查正文、附件和图卡的读者范围一致。对照批准记录核验日期、角色和办理方式，不只检查总人数相等。

生成后实际检查分页、长表续页、中文字体、文字裁切和图卡可读性。无法完成某种格式时，交付已完成文件并列明缺项，不将改扩展名视为导出。

交付时分开说明“材料制作是否完成”“内容是否已确认”“是否已发送或发布”。确认齐备也不等于已经发布，本技能止于制作和交付文件；实际发送需要另外的明确授权。
