# 组织管理简报

帮助管理层看清这次评价覆盖了什么、哪些发现值得关注，以及哪些事情需要组织层面协调或确认。交付的是支持讨论的议题和依据，而不是把全量排名缩成一张难读的表。

评价可以对应活动、阶段或其他业务区间。重点由读者和管理问题决定，不以月份或固定页数决定内容。

## 从管理者要了解的事情开始

资料不足时，简短引导：“把这次评价结果发给我，告诉我简报给谁看、最想了解什么。我会先提炼重点，缺少依据的地方再具体问你。”

读取现有结果、质量说明和管理关注点，识别业务范围、数据截止及规则版本，不要求用户制作专用事实包。理解哪些指标对应交付、质量或其他实际工作；只有分数标签而没有业务定义时，先核对含义，不凭名称编故事。

先确认读者能看哪些对象、字段和汇总信息，再制作正文、附件及图表。仅获准查看部分范围时，说明这是范围内简报；不借组织报告展示未授权明细。

## 先判断总体结果能代表谁

核对结果和质量说明来自同一次数据版本。正式排名、待定结果、未参评对象分别表示，不在写简报时重新计算另一套资格或排名。

- 范围说明区分本次应有对象、实际收到数据的对象和综合参评对象；各项覆盖率使用相应原始有效数据及明确分母。
- 总分均值、中位数和分布基于说明过的参评池；不把未参评当0分，也不把补值计作原始完整数据。
- 各指标使用相同定义和合适样本池。量尺不同的分数不能直接判断哪个业务最差；比率不能把不同分母的百分比简单平均为整体比率。
- 数据缺口会改变总体判断时，把限制放在结论附近。已收到对象的小计不能称作组织全量。

样本很少时用实际数值或点图，不制造看似稳定的分布规律。只有两次可比记录时描述前后变化；范围、规则或对象构成改变时先说明影响，不称为持续趋势。

## 从差异中挑出管理议题

优先选择涉及多个对象、跨岗位配合、规则一致性或已有明确业务影响的事项。分数差距只是发现线索；没有证据时，不自行补出预算缺口、能力不足或某部门失职。

| 发现 | 简报应如何表达 |
| --- | --- |
| 多个范围出现同项差距 | 说明涉及对象、比较依据和覆盖程度，提出核对明细或统一口径的议题，不直接宣布共同根因 |
| 少数对象缺关键数据 | 说明缺项影响哪些结论，列出需要补交或确认的事项，不把缺失当低绩效 |
| 已有明确业务影响记录 | 引用影响的对象、时间及证据，再讨论需要组织协调的选项 |
| 台账显示措施已实施 | 分开写实施状态与效果证据；没有复核结果，不写问题已解决 |

每个议题让读者知道：发生了什么、依据是什么、还有什么未知、可考虑什么选项、需要哪个角色确认。只保留真正有依据的重点，不凑固定条数。

## 将事实、解释和决定分开

事实用数据与来源支撑；解释注明尚待验证；建议说明要取得什么证据或协调什么；正式动作只引用已有确认记录。未知责任人和期限不编造，可以提出需确认的岗位。

历史整改、获奖或风险材料没有提供时，省略对应内容或明确无法判断。低分本身不证明事故、违规或措施无效；排名靠前也不自动构成获奖资格。

## 交付一份能用于讨论的简报

围绕“范围与总体情况—关键发现—待协调或待确认事项—数据限制”组织正文。可以用两页讲清，证据较少时更短，明细较多时放附件；遵循用户已有模板和篇幅要求。

按任务交付可编辑文档、同版PDF或横版汇报图卡。图表只在有助理解分布或差距时使用，注明指标、单位、比较范围和样本数；各格式引用同一组数据，保留图表数据与来源定位，不独立编写数字。

文件生成后核对文字、图表和底表一致，并检查表格、分页与中文可读性。工具无法生成指定格式时说明缺项，不能将一段回复称为已生成的文件。

将简报交给管理层审阅，将数据疑点交给来源岗位；报告中的待议事项不会自动变成已批准任务。结尾指出可讨论的结论和仍需确认的事项，不发送通知、不实施整改、不扩大为行动管理系统。
